# BusNow!!

富士見台（川崎市高津区）と溝の口駅南口のあいだだけを映す、停留所の看板です。検索もしません。地図も出しません。立っている停留所を選ぶと、次のバスだけを出します。

世界観は [docs/CONCEPT.md](docs/CONCEPT.md) に書いてあります。見た目も画面の分かれ方も、そこから決めています。

## 画面

- トップは「富士見台発」と「溝の口駅南口発」だけです。
- **富士見台発**は途中の停留所です。東急バス【溝22】と川崎市バスの接近情報を、両方、あと何分かで出します。バスが何台いても、近い順に全部出します。30秒ごとに更新します。
- **溝の口駅南口発**は始発の停留所です。リアルタイムの接近は使いません。東急バスと川崎市バスの公式時刻表を、平日・土曜・休日で読み、富士見台方面の次の3本を混ぜて出します。きょうの運行が終わっていれば、そのことを書いて、次の朝の3本を出します。

停留所の表記は、事業者のサイトに合わせています。東急バスは「溝の口駅南口」、川崎市バスは「溝口駅南口」です。

## 動かし方

Node.js 22 以降。

```bash
npm install
npm test
npm run dev
```

開発サーバーは <http://127.0.0.1:43123> です。スマホの同じネットワークから見るときは、このマシンのアドレスでポート `43123` を開いてください。

## データの出どころ

サーバー側で公式ページを取りにいきます。ブラウザから直接は取りません。

- 東急バスナビの路線別運行情報（溝22）。富士見台より蟹ヶ谷側にいる溝口南行と、(折)の短絡も、全部出します。停留所の接近ページは手前6停留所までしか出さないので使いません。
- 川崎市バスナビの接近情報（富士見台 → 溝口駅南口）
- 東急バスの公式時刻表（溝の口駅南口・溝22 蟹ヶ谷ゆき、改定 2025-07-01）
- 川崎市バスナビの時刻表（溝口駅南口 1番のりば、標柱 145384。溝21・溝23・溝25・溝15・溝18）

東急バスの時刻表サイトは、この環境から CloudFront に拒まれることがあります。そのときは、同じ公式ページから取り込んだ時刻（`src/data/tokyu-mizonokuchi.json`）を使い、画面にその旨を出します。ライブで取れたときは、そちらを出します。

川崎市バスの時刻表 HTML は Shift_JIS です。

祝日は、国民の祝日（ハッピーマンデー、春分・秋分の概算、振替休日、国民の休日）で平日・土曜・休日を切り替えています。時刻はすべて日本時間です。

## ホーム画面に置く

このアプリは PWA です。名前は **BusNow!!** です。公開した HTTPS の URL を iPhone の Safari で開き、共有ボタンから「ホーム画面に追加」します。アイコンは BusNow!!、開くと Safari の枠なし（standalone）です。ステータスバーは看板のアスファルト色（`#241c16`）に合わせ、ノッチとホームインジケータのぶんは safe area で空けています。

一度オンラインで開くと、圏外でホーム画面から開いたときは「いまはネットにつながっていません」と出ます。接近と時刻はライブなので、オフラインのあいだはバスの本数を出しません。

トップの看板にはアプリ名を載せていません。ホーム画面のアイコンと、ブラウザのタイトルが BusNow!! です。

## 公開するとき

無料で置くなら **Vercel** です。GitHub の <https://github.com/ChihiroNishioka/BusNow> を Import するだけで、設定はリポジトリ側に入っています。

| 項目 | 選ぶもの |
| --- | --- |
| Framework Preset | Next.js（自動） |
| Root Directory | `./` |
| Build / Install | 空欄のまま（`next build` / `npm install`） |
| Node.js | 22.x（`package.json` の `engines` と `.node-version`） |
| Environment Variables | なし |
| Function Region | Tokyo（`hnd1`）。`vercel.json` の `regions` がこれです。Hobby は1リージョンだけです |

時刻の計算は `Asia/Tokyo` 固定です。サーバーのタイムゾーンが UTC でも、平日・土曜・休日と「HH:MM時点」は日本時間です。環境変数 `TZ` は要りません。

サーバーから次のホストへ外向きの HTTPS が必要です。

- `tokyu.bus-location.jp`（富士見台の接近）
- `kcbn.bus-navigation.jp`（川崎市バスの接近と時刻表）
- `transfer.navitime.biz`（東急バスの時刻表）

`transfer.navitime.biz` は CloudFront で、Vercel のようなデータセンターの IP を 403 にすることが多いです。そのときは同梱のスナップショット（2025年7月1日改定）を出し、画面にその旨を書きます。接近情報はスナップショットでは出せません。`hnd1` は東京なので往復は短くなりますが、IP の拒否は避けられません。Cloudflare Pages は Node の取得処理と合いません。

取得は Node.js のサーバー関数です（Edge ではありません）。1回の上限は 60 秒で、各公式ページは 15 秒で打ち切ります。Hobby の関数上限（300 秒）の内側です。

```bash
npm run build
npm start
```

## このあと iPhone アプリにするなら

いまは、ホーム画面に置けるモバイル Web です。最終的な iPhone アプリへは、二段で行けます。

1. 同じ画面を Capacitor で包み、App Store に出す。接近と時刻表の取得は、いまの Route Handler のままサーバーに残します。
2. そのあと SwiftUI で同じ看板を描き直す。API（`/api/approach` と `/api/departures`）はそのまま使います。

ウィジェットやロック画面の Live Activity は、ネイティブになってから載せる想定です。
